# 对话分叉插件 dialog_fork

在 AstrBot 的同一聊天窗口内为当前 LLM 对话创建分叉点，并在之后将当前对话恢复到任意分叉点创建时的状态。

## 功能

- `/fork [分叉点名称] [注释]`：基于当前对话创建分叉点。不填名称时使用当前时间戳作为名称
- `/jump <分叉点名称>`：将当前对话恢复到指定分叉点创建时的状态。恢复后继续聊天不会修改该分叉点
- `/forkpoint-rename <旧分叉点名> <新分叉点名>`：重命名分叉点
- `/forkpoint-list`：列出当前聊天窗口中创建过的分叉点
- `/forkpoint-remove <分叉点名称>`：删除指定分叉点

所有参数都按空格分隔，因此分叉点名称和注释都不能包含空格。分叉点名称大小写敏感。

## 行为说明

- 分叉点按聊天窗口共享。同一个私聊、群聊或 WebChat session 下创建的分叉点可以互相跳转
- 分叉点本质是“存档点”，不是会继续增长的分支引用。反复 `/jump fp` 会恢复到同一份创建时快照
- 插件使用 AstrBot 原生 conversation 保存分叉内容，`/jump` 时会把当前 conversation 的历史覆盖为存档历史，不会切换到存档 conversation 上继续写入
- 插件命令不会写入 LLM 历史
- “段对话”按用户主动发送给 LLM 的 user 消息数量计算，以 `/` 开头的命令消息不计入
- 执行配置项中的重置命令后，插件会在命令回复发送完成后清空当前聊天窗口的分叉点。默认监听 `/reset` 和 `/new`
- 如果某个分叉点对应的存档 conversation 已被外部删除，`/jump` 时会提示“不存在或已失效”，并清理该分叉点记录
- 触发 `/jump` 时会一并将 `persona_id` 也恢复为创建分叉点时的值，如果在 `/fork` 之后又切换了 persona，这一点需要注意
- 助手主动推送内容不会被本插件计入对话历史，插件只读取 LLM Conversation History，不会读取平台实际发送记录

## 配置

在 AstrBot 管理面板中可以配置：

- `reset_commands`：执行后清空分叉点的命令列表，默认 `["/reset", "/new"]`
